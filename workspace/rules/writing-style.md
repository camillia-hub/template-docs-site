# Writing style rules

- Plain English, second person ("you"), present tense, active voice: "Run the
  command", not "The command should be run".
- Sentences are short; one idea per sentence. Procedures are numbered steps, one
  action per step.
- Every command and code sample is copy-paste runnable as written; use
  placeholders like `<project-id>` and explain them on first use.
- American English spelling; code terms, flags and file names use `code`
  formatting.
- No marketing language in docs; state facts and behavior.
- Every page answers: what is this, when do you need it, how do you do it, where
  to go next.
- Screenshots only when the UI cannot be described in one sentence; every image
  has alt text and lives in `docs/assets/`.
